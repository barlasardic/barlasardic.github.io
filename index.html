// The Engineering Problem

4 Step sequencer with a 12-bit DAC output. The challenge was to get a noise-free secured output from the Nano module. This combines physical hardware controlled by potentiometers and a button on an Arduino Nano with a Python-based digital sound synthesis (DSP) engine. In the system, the Arduino Nano reads data from the potentiometers which determine the frequency, tempo (BPM), and waveform (sine, triangle, sawtooth, square) of the four melody steps as well as from the start/stop button, and transmits this data continuously to the computer via the serial port.

// Project Overview

x86 kernel written from scratch. The boot path runs loader.s → gdt.cpp → kernel.cpp, linked by a custom linker script and built with the included Makefile.

kernel.cpp i686 · QEMU target 
#include "types.h"
#include "gdt.h"

void printf(const int8_t* str)
{
        static volatile uint16_t* VideoMemory = (volatile uint16_t*)0xb8000;
        uint8_t fg = 0x0F; // ön plan beyaz
        uint8_t bg = 0x00; // arka plan siyah
        uint16_t color = (bg << 4) | fg;

        for(int i = 0; str[i] != '\0'; ++i)
                VideoMemory[i] = (color << 8) | str[i];
}

typedef void(*constructor)();

// My Outlook

Software DAWs are convenient but knobs, jacks, and voltages are the ones that makes us feel the sound. I build physical instruments because a circuit is just code you can touch. When a module misbehaves, all you got is your bare hands and a multimeter to debug it. That's the spirit of the engineering to me.

Every project starts on the breadboard, gets worked on the bench, and only earns a life once it can't be disassembled any further. I care about the signal path from the DAC pin to the output jack and the noise that I make.
